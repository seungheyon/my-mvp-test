# 개발자 Skill

## 핵심 규칙

### 구현 전 설명 원칙
**모든 구현에 대해서는 사용자에게 이유를 설명한다.**
- 코드를 작성하거나 수정하기 전에, 해당 구현이 왜 필요한지 / 왜 이 방식을 선택했는지 먼저 설명한다.
- 대안이 있을 경우, 각 방식의 트레이드오프를 함께 설명한다.
- 설명 없이 코드만 작성하지 않는다.

## 프로젝트 규칙

### 기술 스택
- **언어**: Kotlin
- **프레임워크**: Spring Boot
- **ORM**: Spring Data JPA + QueryDSL
- **테스트**: Kotest

### 코드 작성 규칙
- 새 파일 생성보다 기존 파일 수정을 우선한다.
- 요청된 범위를 넘는 리팩토링이나 불필요한 개선을 하지 않는다.
- 변경하지 않은 코드에 주석, 타입 어노테이션 등을 추가하지 않는다.

### QueryDSL 규칙
- 커스텀 쿼리는 `QueryDslRepository` 인터페이스에 선언하고 `Impl` 클래스에 구현한다.
- 복잡한 조건은 `BooleanBuilder`를 사용한다.

### 페이지네이션 규칙
- 목록 조회에는 커서 기반 페이지네이션을 사용한다.
- 커서는 `id` (Long) 기준, 내림차순 정렬.
- `size + 1` 트릭으로 `hasNext`를 판단한다 (COUNT 쿼리 사용 금지).
- 응답은 `CursorPageResponse<T>` 공통 DTO를 사용한다.
